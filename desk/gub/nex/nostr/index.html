People

On nostr a person is a public key: 64 hex characters, or the same number written as npub…. There is no directory; you know someone by their key. follows.json is the list of keys whose posts the relay clients ask for. What we know about each person is their own profile event (kind 0), kept as profiles/<pubkey>.json and replaced whenever a relay sends a newer one.

Relays

A relay is a plain websocket server anyone can run. It stores the events people send it and answers subscriptions: a client opens a socket, sends ["REQ", …filter], and the relay streams every matching event it has, says EOSE (end of stored events), then keeps the socket open and pushes new ones as they arrive. There is no login and no single relay; the same post usually arrives from several, and is stored once, by id. Each client here is one fiber holding one socket. live means the socket is open and the stored history is in; a client that loses its socket reconnects on its own, waiting a little longer after each failure. Each writes its state to relays/<host>.json.

Profile

Your identity is one keypair. The public key is your name on the network (me/identity.json). The private key signs everything you publish and is the only proof a post is yours (me/secret.json); it never leaves this ship. Anyone holding it can post as you, so treat the reveal below like a password.

What others see

Saving writes me/profile.json and publishes it as your kind-0 event to every connected relay. Relays keep only the newest one per key, so this replaces what they had.

Posts

A post is a kind-1 event: your key, a timestamp, the text, a signature. It is written to outbox/<id>.json first, then pushed down every open relay socket; each relay answers OK (accepted or not) and that verdict lands in the same file. Publishing needs a key (Profile tab).
