# The comment on the PR

What the audit posts on the pull request's thread. Half a page at most,
GitHub markdown, read off the report: nothing is judged anew here. Two
readers, addressed in turn. Public, under the ship owner's name:
precise, plain, no praise, no hedging, no jargon.

## Shape

1. **One opening line**: that this is an automated audit by the
   repository's clanker, reading only, nothing run; and that the full
   report, with the account, the findings and the objections, is in the
   chat named, on the forge.
2. **Recommendation**: the value and the rule that gave it, one line.
3. **For the reviewer**: the grades as one compact table, question,
   value, one-line reason; then where to look, the files and lines that
   decide the case, as a short list.
4. **For the author**: the required changes, as bullets, each one
   sentence, each something the author can do; then what the standard
   asks that the request left out, one line per missing part: the
   understanding of the parts touched, the problem and how the author
   knows, the solution mechanically, the alternatives considered, tests
   someone else could run. A part the request has is not mentioned.
5. **Tests that would show it**: the testing plan's bullets, verbatim or
   shortened, so the author can run them.

## What it never does

- Restate the report's prose. The comment points; the report explains.
- Soften a grade or a recommendation. The rule gave it.
- Address the author as a person: no thanks, no encouragement, no
  judgment of them. The case is judged, not its maker.
